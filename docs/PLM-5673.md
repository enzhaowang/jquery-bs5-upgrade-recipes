## Ticket 原文

### Background

The jQuery upgrade contains many repetitive changes across modules. Our existing upgrade notes already identify recurring changes such as:

- `.size()` → `.length`
- `.bind()` / `.unbind()` → `.on()` / `.off()`
- `.delegate()` → `.on()`
- Update jQuery/jQuery UI references
- Use jQuery Migrate to identify deprecated APIs

These are currently repeated manually when upgrading different modules.

### Objective

Evaluate whether **OpenRewrite together with jscodeshift-based recipes** can automate the repetitive jQuery upgrade work for the **Non-Sourcing module**.

The idea is to define reusable migration recipes/rules once and then apply them to other modules.

### Expected outcome

Provide a short evaluation covering:

- Which jQuery changes were successfully automated.
- Which changes still required manual work.
- Examples of the jscodeshift recipes created.
- Issues or limitations found.
- Whether the approach can be reused across other modules.
- Recommendation: **adopt / continue POC / not suitable**.

### Success criteria

The POC is successful if we can demonstrate that common jQuery upgrade changes can be captured as reusable recipes and applied to additional code with less repetitive manual modification.

UI/layout differences will still need separate verification.

## 自动化场景

| # | 场景 | 升级原因 | 处理方式 |
|---|---|---|---|
| 1 | 替换 business JS 中的旧语法，不改非 business JS | jQuery | 自动转换，路径白名单限定范围 |
| 2 | 替换 GSP 内联 JS 中的旧语法 | jQuery | 保护 Groovy 语法后自动转换 |
| 3 | GSP 中的 `data-*` 改为 `data-bs-*` | Bootstrap 5 | 自动转换，动态值写入报告 |
| 4 | 把 `active` 从 `li` 移到链接，并修复 JS 中的 `li.active` | Bootstrap 5 | 只自动修改可确认的导航，其余写入报告 |
| 5 | Business JS 生成的 HTML 模板中的 `data-toggle` 等写法 | Bootstrap 5 | 自动转换，动态拼接写入报告 |
| 6 | Inspinia 升级 | Inspinia 4 | 暂不自动化，人工处理 |
